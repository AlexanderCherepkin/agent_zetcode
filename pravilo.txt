⚡ Полный справочник команд npm run1. Интеллектуальный анализ и парсинг сайтаКомандаОписаниеnpm run agent -- https://site.comРЕКОМЕНДУЕТСЯ! 

1. Интеллектуальный CLI-диспетчер. Делает быстрый пре-скан сайта (детекция 3D, GSAP, кол-ва внутренних ссылок и e-commerce), 
после чего предлагает выбрать идеальный скрипт: глубокий парсинг одной страницы или потоковый многостраничный обход.
npm run extract -- https://site.comНапрямую запускает глубокий обход. Скачивает HTML, CSS, JavaScript, шрифты, 
изображения и все видеоролики локально в assets/media/, распознаёт параллакс и автоматически создаёт эталон Golden Master.

2. Быстрая замена в content.json, синхронизация и ИИ-ребрендингКомандаОписаниеnpm startЗапускает сервер на http://localhost:3000, 
автоматически вшивает изменения из content.json прямо в index.html и включает визуальный редактор Click-to-Edit.npm run syncМгновенно 
запекает все ручные изменения из content.json (тексты, картинки, новые видео) напрямую в файл 
output/site_clone/index.html.npm run rebrand -- "Новая тема сайта"Переписывает тексты в content.json под новую тематику через локальную LLM 
и автоматически синхронизирует их с index.html.npm run rebrand:dictМеняет бренды, телефоны, ссылки, картинки и видео строго по словарю из rebrand-config.json 
без вызова ИИ.npm run build:staticСобирает финальную чистую версию сайта в папку output/dist/ без служебных атрибутов data-agent-*, готовую для хостинга.

3. Защита проекта, проверка и откаты (Agent Guardian)КомандаОписаниеnpm run guardВключает активный надзор в реальном времени, 
блокирует удаление защищённых скриптов и пишет историю состояний (без авто-сброса твоих правок).npm run verifyЗапускает проверку рендеринга в headless-браузере. 
Оповещает при обнаружении белого экрана или пропавших блоков.npm run verify:uiВыполняет ту же проверку, но с видимым окном браузера.npm run history
Показывает записанные шаги агента (step_001, step_002 и т. д.), даты и описания изменений.npm run snapshot -- "Комментарий"
Вручную сохраняет текущую рабочую точку проекта с комментарием.npm run rollbackРучной откат проекта на один шаг назад (спасает при поломке верстки).npm run rollback -- 
3.1 Перемещает проект к конкретному шагу истории, например к шагу № 3.npm run reset-goldenПолностью восстанавливает исходное состояние сайта после парсинга без повторного скачивания.

4. Генерация чистого проекта Next.js + Tailwind + GSAPКомандаОписаниеnpm run generate:baseСоздаёт проект в output/generated_nextjs_project/ 
с движком параллакса ScrollEffectsHandler.jsx, AST-конвертацией DOM в JSX и локальными ассетами.npm run generate:llmУмная нарезка HTML на секции, 
передача их вместе с посекционными скриншотами локальному llama-server для создания модульного app/page.jsx.🛠️ Стандартный рабочий процесс
Шаг 1. Запусти локальный ИИ-сервер (опционально)Этот шаг необходим только в том случае, если планируется автоматический ИИ-рерайт или генерация через локальную LLM. 
Если ты меняешь данные самостоятельно в content.json, этот шаг можно пропустить.Для запуска мультимодального сервера (поддерживающего анализ скриншотов) 
используйте следующую команду в терминале Windows:Bash./llama-server.exe \

Шаг 2. Спарси целевой сайтВ корневой директории проекта выполни:Bashnpm run agent -- [https://target-awwwards-site.com](https://target-awwwards-site.com)
Система проведет пре-анализ и предложит выбрать режим. Команда всегда полностью скачивает:Все видеоролики в output/site_clone/assets/media/Картинки
 в assets/images/Шрифты в assets/fonts/Также она собирает все тексты и ссылки на медиа в единый файл output/site_clone/content.json и создаёт эталон Golden Master.
Шаг 3. Включи СтражаВ соседней вкладке терминала запусти систему защиты проекта:Bashnpm run guard
Страж будет отслеживать изменения, проверять целостность проекта и поддерживать историю для ручного отката.
Шаг 4. Быстрая подмена текстов, картинок и видео в content.jsonОткрой файл output/site_clone/content.json. 
Вся структура сайта собрана в четырёх блоках:"texts" (txt_1, txt_2...) — все заголовки, описания и кнопки."images" (img_1, img_2...) — пути ко всем скачанным картинкам 
(./assets/images/...)."videos" (vid_1, vid_2...) — пути ко всем скачанным видеороликам (./assets/media/...).
Tip: Чтобы заменить любое видео на своё, просто положи свой .mp4 / .webm файл в output/site_clone/assets/media/ 
и пропиши его имя в нужном ключе vid_X."backgrounds" (bg_1, bg_2...) — фоновые изображения секций.После ручного редактирования content.json 
запусти сервер предпросмотра (он автоматически запечёт новые данные прямо в index.html):Bashnpm start
Либо принудительно вшей изменения из content.json в index.html одной командой:Bashnpm run sync
Открой http://localhost:3000 в браузере, чтобы увидеть обновлённый сайт, или проверь его авто-тестом:Bashnpm run verify

Обновление модуля загрузки медиафайлов🚀 Что изменилосьВ скрипте src/extractor/playwright-scraper.js полностью удалено жесткое ограничение на размер файла в 45 МБ.
Вместо старых проверок размера внедрена потоковая загрузка (Stream) через библиотеку axios. 
Это позволяет безболезненно скачивать даже тяжелые фоновые видеоролики в разрешении 4K напрямую в целевую директорию.
🛠 Технические деталиСтарая логика: Лимит в 45 МБ, приводивший к ошибкам или пропуску тяжелых файлов.Новая логика: Потоковая передача данных (Streaming) 
без буферизации всего файла в оперативную память.Путь сохранения: Все медиафайлы скачиваются напрямую в папку assets/media/.
